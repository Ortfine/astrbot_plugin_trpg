# astrbot_plugin_trpg

AstrBot TRPG 插件，在 QQ/TG/Discord 等平台的私聊中实现类 SillyTavern 的轻量角色扮演体验。

## 功能

- **角色卡管理**：对话式创建、一次性粘贴创建（支持字段别名、AI 自由文本整理）、6 个预设模板、单字段编辑（`+` 前缀直接追加）、采访式 AI 建卡/改卡、切换、删除
- **玩法模式**：AI扮演角色 / 玩家扮演角色 / 纯叙事者，创建和编辑时可选
- **主动性模式**：主动带节奏 / 被动跟随 / 攻守兼备，控制 AI 推进剧情的积极程度
- **破甲沉浸协议**：开启后 AI 全程保持角色与叙事，不出戏、不以 AI 身份说教点评，`/破甲` 一键开关
- **采访式 AI 建卡/改卡**：`/AI建卡` 糊入一大段杂乱素材，AI 像编辑一样反问澄清真实需求（最多 6 轮，可随时说「不用问了」），生成含世界书条目的完整角色卡预览，确认「是」才保存；`/改卡 <名字> <要求>` 同款引擎：反问澄清→方案预览→确认才写入（默认追加不覆盖），不占用角色扮演上下文、不动对话历史、全版本 AstrBot 兼容
- **开场白**：角色卡可设置开场白，激活成功后直接发送并自动写入对话历史（不用先开口"撞"设定）
- **状态栏**：开启后 AI 每段回复末尾输出状态栏（时间/场所/情节/角色状态与好感度/内心独白/选项），最近一次快照自动存回角色卡，清空历史也能续上状态，游戏时间自动同步
- **动态世界书**：条目带关键词，玩家消息命中才按需注入（每轮最多 3 条），不命中不占上下文
- **符号系统**：内置（）{}[]""//等符号约定注入角色卡，NPC 可按设定拒绝（）请求、必须执行 {} 指令
- **世界观注入**：角色卡激活后自动将玩法模式、主动性、提示词、世界观、NPC、地点、剧情主线、游戏时间注入 AI 上下文
- **世界书日志**：激活角色卡期间逐轮自动记录对话到本地 JSONL（零额外开销），可关键词检索、可按需调用 AI 提炼设定
- **剧情总结**：`/总结剧情` 压缩长历史写入角色卡世界观（自动备份、防膨胀），解决长剧情导致的上下文超限和安全拒绝
- **自动家务**（配置面板开启，默认关闭）：自动快照每 N 轮把当前历史轮替存进槽位 8~10（只留最近 3 份）；自动提炼每 N 轮新日志后台蒸馏设定写入世界观（完成后发📚通知）
- **对话回滚**：删除最近 N 轮对话，或 `/回滚 3-5` 精确砍掉中间指定轮，让 AI 重新推进剧情（无需激活角色卡，普通聊天也能用，见下方彩蛋）
- **重roll**：`/重roll` 把最后一条 AI 回复从记忆中删掉，用完全相同的上下文重新生成——AI 答歪了一键重骰，不用手动回滚重发
- **槽位存档**：每张卡 10 个槽位，支持备注、分享码导出/导入
- **注入模式控制**：白名单模式（默认）/ 人格标记模式，避免助理人格被误注入
- **管理员指令**：白名单管理、角色卡管理
- **中文短指令**：常用操作都是中文指令，不用记长串英文

## 安装

将 `astrbot_plugin_trpg` 文件夹放入 AstrBot 的 `data/plugins/` 目录，重载插件即可。

数据默认存储在 `data/plugin_data/astrbot_plugin_trpg/`（角色卡 YAML、`trpg.db` 存档库、`world_log/` 世界书日志），插件更新不会丢失。

## 配置（WebUI 插件配置面板）

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `inject_mode` | `whitelist`（白名单）或 `persona`（人格标记） | `whitelist` |
| `persona_keyword` | persona 模式下的触发关键词 | `#TRPG_ENABLED` |
| `whitelist_umos` | 白名单会话列表，直接在面板里填 umo，每行一个 | 空 |
| `world_log_enabled` | 世界书日志开关：激活角色卡期间自动逐轮记录对话 | 开 |

**白名单模式**：默认所有会话都不注入角色卡，有两种方式开启：

1. 在目标会话里发 `/trpg admin whitelist add <umo>`（管理员）或 `/trpg admin whitelist me`（在该会话里自己执行，自动加入当前会话）
2. 直接在 WebUI 插件配置面板的 `whitelist_umos` 列表里逐行填入 umo，保存并重载插件后自动同步进白名单

两种方式可以混用，配置面板的内容只会增量添加，不会覆盖通过指令添加的记录。umo 的具体格式可以先用 `/trpg admin whitelist me` 在目标会话里跑一次，然后 `/trpg admin whitelist list` 查看准确写法，再填回配置面板。

**人格标记模式**：在角色扮演用的人格 system prompt 里加上 `#TRPG_ENABLED`（或自定义关键词），插件检测到该标记才注入角色卡，助理人格不受影响。

## 角色卡文件格式

角色卡是 YAML 文件，存储在 `data/plugin_data/astrbot_plugin_trpg/cards/` 目录下，也可以手动创建：

```yaml
name: 角色名
description: 角色描述（外貌、性格等）
world: 世界观设定（背景、规则等）
system_prompt: 系统提示词（AI 行为指导）
opening: 开场白（激活时直接发送并写入历史，可留空）
play_mode: AI扮演角色  # 或 玩家扮演角色 / 纯叙事者
initiative: 攻守兼备    # 主动性模式：主动带节奏 / 被动跟随 / 攻守兼备
status_bar:
  enabled: false        # 状态栏开关
  prompt: ""            # 自定义状态栏规则，留空用默认模板
status_snapshot: ""     # 最近一次状态栏快照（插件自动维护，无需手填）
jailbreak: false        # 破甲沉浸协议开关（/破甲 开）
jailbreak_prompt: ""    # 自定义沉浸协议文本，留空用默认
lore_entries: []        # 动态世界书条目：name/keywords/content，关键词命中才注入
game_time:
  current: 王历1204年 春
npcs: []        # 可选：name/role/personality/reaction_rules/current_state
locations: []   # 可选：name/desc
plot_lines: []  # 可选：id/title/trigger/desc/branch_hint
```

## 注意事项

- 角色卡激活后，根据 `inject_mode` 配置决定是否注入，不是激活了就一定生效
- `/回滚` 回滚的是 AI 的对话历史，每轮包含一条用户消息和一条 AI 回复
- `/读档` 会覆盖当前对话历史，建议先 `/存档` 备份
- `/总结剧情` 前会自动备份当前历史（优先空槽，槽满覆盖槽位 10 并提醒）
- 角色卡世界观中的「剧情记录」块最多保留 5 块，超出自动移除最早的（完整历史仍在世界书日志里）
- 状态栏快照、游戏时间由插件自动维护，手动改 YAML 时别动 `status_snapshot`
- 创建/编辑角色卡过程中，发送 `/cancel` 或「取消」可随时退出
- 开启自动快照后，槽位 8~10 被自动快照轮替占用，手动存档请用槽位 1~7

## 💡 彩蛋：普通聊天里也很好用

`/回滚` 并不依赖角色卡——它操作的是 AstrBot 本身的会话历史，所以**任何正常聊天里都能用**。
一个实测好用的场景：**模型拒绝了你的请求时，先 `/回滚 1` 再换种说法重试，大概率就同意了。**

原理：模型上一轮的拒绝会留在对话历史里，成为"这个话题不该配合"的先例，让后续请求越来越难通过；
`/回滚 1` 把那次拒绝从历史里删掉，等于抹掉了这个先例，重新措辞后模型往往就顺着新的说法走了。
同理想被打断的话题、答歪的回答，都可以 `/回滚 1`（或 `/重roll`）一键重来。

## 常见问题（FAQ）

**Q：/改卡 或追加设定后，AI 不立刻按新设定演？**
不是设定没进上下文——每次请求都会重新注入角色卡，写入的下一条消息起新设定就已经在了。你感觉到的"惯性"是对话历史的行为模式在带节奏。从轻到重的解法：
1. 下一条消息用 `//` 或 `（旁白：）` 点一句新设定，九成情况一两轮就扳回来
2. `{ }` 强制指令（符号系统最高优先级，AI 必须执行）
3. AI 刚回的内容和新设定矛盾：`/回滚 1` 砍掉重发
4. 设定大改（性格反转、世界观翻转）：`/总结剧情` 软重启——当前状态压进世界观、清空旧历史，状态栏快照还在
5. 完全清空重来永远是最后手段，一般轮不到

**Q：AstrBot 日志警告 "Plugin astrbot_plugin_trpg has no changelog file"？**
无害警告：插件管理器想找 CHANGELOG.md 显示更新内容。v0.5.2 起已内置该文件，不会再出现。

**Q：自动快照 / 自动提炼在哪开？**
默认关闭（避免悄无声息消耗存储和 LLM 额度）。在 AstrBot WebUI 的插件配置面板把 `auto_snapshot_turns` / `auto_distill_turns` 设为大于 0 的轮数即可（建议快照 10~20、提炼 20~30）。

**Q：自动提炼会不会把角色卡越写越大？**
不会。「剧情记录」「设定提炼」「自动提炼」三类块各自最多保留 5 块，超出自动移除最早的；完整历史永远在世界书日志里，可用 `/查档` 检索。

**Q：我的角色卡、存档、日志存在哪？升级插件会丢吗？**
全部在 `data/plugin_data/astrbot_plugin_trpg/`（cards/、trpg.db、world_log/），不在插件本体目录。升级插件只动代码目录，数据完全不受影响。
